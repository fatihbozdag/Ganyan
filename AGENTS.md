# Repository Guidelines

## Project Structure & Module Organization
Ganyan is a Python 3.12+ Turkish horse-racing prediction system. Source lives in `src/ganyan/`: `scraper/` retrieves TJK data, `db/` defines SQLAlchemy models and sessions, and `predictor/` contains feature engineering, LightGBM (`ml/`), and Bayesian (`bayes/`) models. `cli/` exposes Typer commands; `web/` contains Flask routes and Jinja templates. `scheduler.py` coordinates background jobs. Database migrations live in `alembic/`; tests mirror modules under `tests/`. Operational scripts and documentation live in `scripts/`, `ops/`, and `docs/`.

## Build, Test, and Development Commands
- `uv sync --all-extras`: install locked dependencies, including development, Bayesian, and GUI extras.
- `uv build`: build the package using Hatchling.
- `uv run alembic upgrade head`: apply migrations to the configured database.
- `uv run ganyan --help`: inspect available CLI commands.
- `uv run python -c "from ganyan.web.app import run; run()"`: start the dashboard on port 5003; normal startup also runs background work.
- `uv run pytest tests/ -v`: run the full test suite.
- `uv run pytest tests/test_predictor/ -v`: run predictor tests only.

## Coding Style & Naming Conventions
Use four-space indentation, `snake_case` functions/modules, `PascalCase` classes, and uppercase constants. Follow neighboring code for type annotations, imports, and docstrings. Keep data access, prediction logic, and presentation in their existing layers; preserve Turkish interface terminology. No formatter or linter is configured in `pyproject.toml`; avoid unrelated formatting changes.

## Testing Guidelines
Use pytest, pytest-asyncio (automatic mode), and respx for mocked HTTP requests. Name files `test_*.py` and functions `test_*`; reuse fixtures in `tests/conftest.py`. Add tests for new features and regressions, especially temporal leakage, model provenance, and guard behavior. Run tests before opening a PR. No minimum coverage threshold is configured; optional coverage is available through `--cov=ganyan`.

## Commit & Pull Request Guidelines
Follow the history's `type(scope): summary` convention, such as `fix(features): close temporal leaks`. Keep commits focused. PRs should describe behavior changes, validation commands/results, relevant issues, and migration requirements. Include screenshots for dashboard changes. Review autogenerated migrations before committing.

## Configuration & Model Safety
Use `.env.example` to configure a local `.env` and a development PostgreSQL database; never commit credentials. Read `CLAUDE.md` before model or operational changes. Keep training candidates isolated from live model files, preserve halt controls, and require the documented out-of-sample gate before promotion.
